# 1.1.0 - Decision / SystemOne inference

**Status:** implementation release notes; publication date not yet assigned.

## Highlights

- Unified AI API now routes Azure OpenAI Decisions and Microsoft Decision-1
  SystemOne requests using each provider's native request/response contract.
- OpenAI Decisions reuses existing Foundry/OpenAI backends. Microsoft uses the
  dedicated `azure-decision` type on a Foundry services root.
- A new validation notebook discovers live backend/model registrations, creates a
  request-governed Access Contract and checks typed answers and routing. Registered
  targets bypass backend onboarding, without a source file or manual capability map.

## Added and changed

| Public POST route | Backend path | Pool types |
|---|---|---|
| `/unified-ai/v1/decisions` | `/openai/v1/decisions` | `ai-foundry`, `azure-openai` |
| `/unified-ai/openai/v1/decisions` | `/openai/v1/decisions` | `ai-foundry`, `azure-openai` |
| `/unified-ai/providers/microsoft/v1/systemone` | `/providers/microsoft/v1/systemone` | `azure-decision` |

New paths are matched ahead of generic chat-oriented prefixes and restricted to
POST. Prefix lookalikes/descendants are rejected. The gateway strips inherited
`api-version` on these routes, preserving other query values and native bodies.
The metadata cache namespace advances to `1.1.0`.

SystemOne pools are opt-in, including for aliases, defaults and retry candidates.
They cannot become legacy chat/Responses fallbacks. Discovery exposes the new
native capability without advertising it as chat; explicit OpenAI `operations`
metadata can advertise Decisions alongside existing capabilities.

## Compatibility and adoption

Existing backend/access contract files require no changes. Existing routes,
authentication, priorities, weights and model grants keep their behavior.
To adopt the feature:

1. Use already deployed, supported models in available regions.
2. Reuse an OpenAI/Foundry backend; add `azure-decision` only for Microsoft.
   Its endpoint is `https://<account>.services.ai.azure.com/`, without a provider
   path. Keep the complete predecessor source, aliases and global settings.
3. Follow the [two-stage gateway
   upgrade](../bicep/infra/apim-gateway-upgrade/README.md#decision--systemone-release-upgrade).
   Update common fragments/API/version first with dynamic `updateLLM*` flags
   disabled, then use full-source backend onboarding for dynamic artifacts.
   Do not reprovision the hub/landing zone.
4. Deploy a Decision-capable, request-governed product policy. Existing token-only
   products are not automatically certified for the new schemas.
5. Verify `/version`, `/version/backend-contract`, fresh/cached routing, new
   provider calls and legacy smoke tests.

## Validation

The [Decision notebook](../validation/citadel-decision-models-tests.ipynb) covers
both OpenAI route aliases, predicate/noul, choice, score, multiple questions,
image/JSON input, answer bounds, usage and routing headers. It also checks
auth/model errors, RBAC where an ungranted deployment is available, unsupported
methods/paths, compatible pools and isolated bounded request-rate/quota probes.
Unavailable providers are explicit skips; configured failures remain failures.

Offline coverage executes the actual APIM C# expressions and actual notebook
generation cells, checks preserved contracts and validates response shapes.
Local implementation verification:

- **84 focused tests passed**, including native payload/answer validation, the
  actual APIM expressions, complete notebook Run All with mocked cloud boundaries,
  unchanged contract helpers and existing routing/capability regressions.
- **Initial deployment, backend onboarding and gateway-upgrade Bicep builds
  passed**; existing template warnings remain.
- Unchanged legacy backend parameters, additive Decision backend parameters and
  the generated request-governed Access Contract compiled successfully.
- The broader 472-test run reported seven failures and two errors in existing
  JWT/PII/VPN/notebook checks and the Matplotlib environment. The same seven
  failures and two errors were reproduced with pre-change test sources and the
  new notebook excluded; this is not a clean full-suite sign-off.

Follow-up Run All verification:

- **90 focused offline tests passed**, including live-first discovery with stale
  azd inventories, automatic helper reload, native Microsoft response fields and
  standard APIM error bodies.
- Run All completed discovery, Access Contract deployment and every test without
  backend reconfiguration. Both providers returned usable typed decisions.
- The live verdict was **27 PASS, 2 FAIL, 2 SKIP**. The two failures were OpenAI
  requests sent by the existing pool to East US 2, which returned HTTP 400
  unsupported-operation responses; Sweden Central requests succeeded. The two
  skips were RBAC probes without an available ungranted Decision deployment.
- Validation products were created/reused. Backends, pools and routing fragments
  were left unchanged. The notebook correctly retains a failed overall verdict
  for those real provider failures rather than hiding them.

Migration/rollback remains unverified in a live environment.

## Known limitations

- OpenAI uses `input` plus question/answer arrays; Microsoft uses `state` plus
  named objects. No translation or cross-schema failover is provided.
- Neither API adds a GET/DELETE lifecycle or streaming endpoint here.
- Model and region availability follows the providers' current rollout.
- APIM built-in token limits/metrics do not document these Decision schemas.
  Decision contracts use request limits; returned usage is preserved, not
  fabricated or automatically ingested as Decision token telemetry.
- Custom token accounting and content/PII/semantic-cache adapters are deferred.
- Automatic notebook deployment can modify shared routing. Shared backend
  additions are retained; cleanup defaults off and deletes only run-owned products.

## Rollback

Retain the previous release and full approved backend source before upgrading.
Restore common/API/version artifacts using the same scoped upgrade flags, then
restore the prior effective contract through that release's onboarding module.
Keep shared infrastructure and predecessor access contracts. Preview any removal
of newly added Decision resources separately. Allow cached metadata to expire
(300 seconds) or use an approved reset, then verify the restored version and
legacy routing before closing the rollback.
